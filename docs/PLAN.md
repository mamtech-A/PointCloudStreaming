# Plan: Add a DQN-based ABR agent + OO topology refactor

> This file lives in the project so you can comment on it directly. It mirrors the working plan.
> The **Object-oriented topology** section (▶ §2) is being generated by a design workflow and will be filled in shortly.

## 1. Context

`PointCloudStreaming` is a DASH-style **simulator** for volumetric (point-cloud) video. Today it has two
representation-selection (ABR) strategies, both in [src/network_model.py](src/network_model.py):

- **Baseline** `EdgeNode._bandwidth_selection` — pick the highest rep whose bitrate ≤ 80% of the harmonic-mean
  observed throughput.
- **LSTM-rule** `EdgeNodeLSTM._select_quality_level` — feed observed throughput to a trained LSTM
  ([src/lstm_model.py](src/lstm_model.py)), get a predicted bandwidth, then map it to a quality tier with
  **hardcoded** Mbps thresholds (≥20→high, ≥5→med, else low).

The user wants to **add a third strategy: a DQN agent that learns to select the representation per frame**, while
**keeping the LSTM** — the LSTM's bandwidth prediction becomes one input feature to the RL state, alongside other
signals (buffer level, last quality, recent throughput, per-rep sizes/densities). This replaces the hand-tuned
threshold logic with a learned policy optimizing a Pensieve-style QoE reward.

The user also wants the project restructured into a clean **object-oriented topology**: `Server → EdgeNode →
User(s)` as first-class objects, where *connecting a user to an edge node* is a natural operation, the `Server` is
its own object, and the server↔edge link exists as an object even though it is currently unconstrained.

**Decisions confirmed with the user:** all state features (LSTM prediction always included), Pensieve-style QoE
reward, full pipeline (env + agent + training + inference + comparison); feature set is **toggleable** for ablation
("trial and error"); `network_model` becomes a **package** with `tcp_protocol` moved inside it.

## 2. Object-oriented topology (Server → EdgeNode → User)

_Recommended design: **Session-centric topology with explicit links**. Chosen via a 4-proposal design workflow
with adversarial judging (Session-centric & Explicit-Link tied at 39/50; merged). All decisions resolved in §10._

> **Scope decision — single user for now.** We build and run with **one user / one session** for the time being.
> The OO topology (Server / EdgeNode / User / StreamingSession / links / `ABRStrategy`) is built anyway because it's
> what makes the code clean and *ready* for multi-user — but **multi-user bandwidth allocation/contention is
> deferred** until a better bandwidth dataset is available (see §2.9). With one user there is no allocation
> question: the trace is simply that user's access-link capacity (today's behavior, preserved). Decisions #1–#7
> still hold and degenerate cleanly to the single-user case (frame-outer loop = step the one session; `user_id`
> column = one constant value; one ABR strategy instance; one LSTM predictor).

### 2.0 Two real bugs this refactor fixes (found during design)
1. **Multi-user ABR cross-contamination.** Per-user transport (`tcp_connections`, [src/network_model.py:139](src/network_model.py#L139))
   is keyed by `user_id`, but the ABR state that drives selection (`bandwidth_history`, `observed_throughput_history`,
   `quality_history`, `last_rep_id`, LSTM `prediction_history`) lives **flat on the `EdgeNode`**. Connect a second
   user to one edge and their histories + LSTM warm-up cross-contaminate, corrupting ABR (and DQN training). A
   `StreamingSession` owning per-user state fixes this **by construction** — exactly what your multi-user + DQN goal needs.
2. **File-handle bug.** `Simulator.run` calls `csv_file.close()` **inside** the per-client loop (~line 954), so a
   second client writes to a closed file. The topology-driven loop opens files once and closes after all sessions.

### 2.1 Why this approach
- **Base = Session-centric**, because the deciding factor is bug #1, not OO taste. The session is the natural unit
  that owns per-user state, ABR strategy, buffer, and the access link.
- **Links reified** (from the Explicit-Link proposal): `BackhaulLink` (Server↔Edge, unconstrained today) and
  `AccessLink` (Edge↔User, the TCP+trace bottleneck) become real objects, so the bottleneck is visible in the
  object graph and a future backhaul constraint is a one-class change.
- **Rejected over-engineering** (from the graph-model proposal, 33/50): no generic `Node`/adjacency/`path()`
  machinery and no separate `CapacityModel` hierarchy — not needed for multi-user/multi-edge.
- **ABR extracted to a Strategy object** (not `EdgeNode` subclasses) — **[DECIDED ✓]**: the only clean way to
  express "DQN's state contains the LSTM's prediction" is composition (`DQNABR(lstm_provider=LSTMABR(...))`).
  **One ABR policy per edge, shared by all its users** (not a different policy per user); each session still gets
  its **own strategy instance** for per-user state isolation (§2.7), with the heavy LSTM/DQN model weights loaded
  once and shared read-only across instances.

### 2.4 Connect-a-user API
The ABR **policy is set once on the edge** (all its users share it); each connected user just supplies its trace.
```python
edge = EdgeNode("edge-1", server, abr_factory=lambda: LSTMABR(predictor), tcp_params=tcp_params)
# edge-centric (returns a session); the session's strategy is minted by the edge's factory
session = edge.connect_user(user, trace=trace)
# topology-centric (preferred; also registers the session for the Simulator)
session = topo.add_user(user, edge, trace=trace)
```
`connect_user` calls the edge's `abr_factory()` to mint a fresh per-session strategy instance (same policy for
all users, isolated per-user state), builds the `AccessLink` (with a per-user `TCPConnection`, established lazily
like today's `tcp is None or tcp.closed` check at line 196), constructs the `StreamingSession`, and registers it.

### 2.5 Server as a first-class object + unconstrained backhaul
`Server` (renamed `PointCloudServer`, bodies unchanged) never references users/edges — reachable only via
`BackhaulLink`. The Server↔Edge segment is a **real object today** with `capacity_bps=None` (infinite),
`transfer()` returning `time_s=0.0`. `StreamingSession.step()` already routes the fetch through
`backhaul.transfer(...)` and sums its time — so the seam is **wired now**. Adding a constraint later =
set `edge.backhaul.capacity_bps` and model the delay analytically (`data_bits/capacity_bps`); **no change** to
EdgeNode/User/buffer/ABR/Simulator.

### 2.8 Usage snippet
```python

from src.network_model.abr import BandwidthABR, LSTMABR, DQNABR
from src.network_model.trace import BandwidthTrace
from src.lstm_model import LSTMPredictor

                abr_factory=lambda: DQNABR(policy="models/abr_dqn.pt", lstm_provider=LSTMABR(predictor)))
topo.add_edge(edge)                              # BackhaulLink(server, edge), capacity_bps = None

# SINGLE user for now (the trace is this user's access-link capacity). Adding more users later is the SAME call
# — but only meaningful once a shared-capacity allocation is added (§2.9), pending a better dataset.
topo.add_user(User("user-A"), edge, trace=BandwidthTrace.from_log("data/bandwidth/report_foot_0006.log"))

sim = Simulator(topo, duration=10.0)
sim.run(mpd_path="config/mpd.xml")               # logs/results.csv carries a user_id column (one value for now)
for s in topo.all_sessions():
    print(s.user.user_id, s.qoe())
```

### 2.9 Bandwidth & multi-user scope (deferred)
- **Now (single user):** one bandwidth trace = the user's `AccessLink` capacity, consumed one sample per frame
  (today's behavior). No allocation needed. This is what we implement and verify first.
- **Why multi-user is deferred:** with independent per-user traces, N users = N parallel single-user runs (no
  interaction) — which defeats the purpose. Meaningful multi-user requires a **shared, contended capacity**, and
  the current 40 traces are **per-device**, not a shared-link aggregate. So multi-user waits for a **better
  bandwidth dataset**.
- **Reserved extension point (no rework):** when ready, give the `EdgeNode` a shared `capacity(frame_idx)` and have
  the **frame-outer loop** split it among active sessions via an allocation policy (equal share `C/N`, max-min, or
  weighted-by-buffer) before each `session.step(...)`. The OO structure (Topology / per-session state / links /
  per-session ABR) already supports this; only the allocation step is added — `EdgeNode`/`User`/`buffer`/`ABR`
  stay untouched.
- **To revisit then:** the new dataset's nature (shared-link vs per-device), the allocation policy, and whether
  users also have individual ceilings (hybrid). (§10.9)

## 3. RL specification

- **Action**: discrete `rep_id ∈ {0,1,2}` (high / medium / low quality) for the current frame.
- **State** (default 14-dim; each block individually toggleable via `feature_spec`, normalized with fixed
  constants — no per-episode min/max, to avoid leakage):
  | feature | source | normalization |
  |---|---|---|
  | `lstm_pred` | LSTM predicted bandwidth (Mbps); harmonic-mean fallback during warm-up | `/100` |
  | `buffer` | `ClientBuffer.buffer_level_s` | `/buffer_capacity_s` |
  | `last_rep_onehot` | previous frame's rep_id | one-hot (3) |
  | `tput_last` / `tput_mean` / `tput_std` | last + short history of observed throughput (Mbps) | `/100`, `/100`, `/50` |
  | `rep_sizes` (3) | current frame's 3 rep sizes (MB) | `/25` |
  | `rep_densities` (3) | current frame's 3 rep densities | `log10(d)/7` |
- **Reward (Pensieve-style, per frame)**:
  `r = quality(rep_t) − μ·stall_time_s − λ·|quality(rep_t) − quality(rep_{t-1})|`
  - `quality(rep) = (log10(density) − log10(30_000)) / (log10(1_060_000) − log10(30_000))` → ≈ {low:0.0, med:0.45, high:1.0}
  - `stall_time_s` = `stall_time_s` returned by `ClientBuffer.add_frame(...)`
  - Start values **μ=4.3, λ=1.0** (one rebuffered second clearly outweighs one quality step). Tunable.
  - Train on this dense reward; **report** the existing end-of-run QoE (`100 − 10·rebuffer − 5·stall − 2·dropped`)
    for apples-to-apples comparison with baseline/LSTM.

## 6. Component designs

### `StreamingEnv` (`src/rl/env.py`)
Wraps **one trace = one episode** by driving a **one-session `Topology`** (a single `StreamingSession`), so the env
and live inference share the same transfer+buffer+feature code path. The DQN agent supplies the action; the env
bypasses `session.abr.select` and applies the chosen rep:
- `__init__(manifest_frames, lstm_predictor, tcp_params, target_fps, buffer_capacity_s, min_buffer_s, feature_spec, mu, lam, throughput_hist_len, seed)`.
- `reset(trace_bandwidths)` → build a fresh one-session topology (`Server`+`EdgeNode`+`User`+`AccessLink` over the
  trace), reset the session's `observed_throughput_history`/`last_rep_id`/`prev_quality` and the LSTM provider's history.
- `step(action)`:
  1. `data_bytes = size_to_bytes(rep['size'])` (manifest `bandwidth` attr is 0 → `rep['bandwidth']/30` is dead code).
  2. `capacity_bps = trace_bandwidths[min(frame_idx, len-1)]` — keep the existing 1-sample-per-frame cadence for
     comparability (document the trace-is-~1/sec mismatch).
  3. `metrics = tcp.send(data_bytes, capacity_bps)`; record throughput (`sent_bytes*8/time_s`) **after** send.
  4. `buf = client_buffer.add_frame(...)`.
  5. compute reward; build next state; `done = frame_idx ≥ len(frames)`; return `(next_state, reward, done, info)`.

### `DQNAgent` (`src/rl/dqn.py`)
- `QNetwork`: MLP `Linear(state_dim,128)→ReLU→Linear(128,128)→ReLU→Linear(128,3)`.
- **Double DQN**, **Huber loss**, Adam `lr=5e-4`, `gamma=0.99`, `batch_size=64`, replay `maxlen=100_000`,
  hard target update every 500 learn-steps, epsilon linear 1.0→0.05.
- **Save format mirrors `LSTMPredictor.save`**: persist `model_state_dict`, `state_dim`, `feature_spec`,
  `norm_constants`, `lstm_model_path`, `mu/lam`, training metadata (lets inference rebuild the identical state).

### Training (`train_dqn.py`)
- Reuse `split_bandwidth_files('bandwith/', 0.1, 42)` — **same 36/4 split as the LSTM**.
- ~40 epochs × 36 traces, shuffle order each epoch; periodic greedy eval on the 4 test traces; checkpoint
  best-by-test-reward to `models/abr_dqn.pkl`. Seed RNGs; fixed-seed eval episodes.

### Inference — `DQNABR` strategy (`src/network_model/abr.py`)
- `DQNABR.select(state: ABRState) -> rep_id`: fill `state.predicted_bandwidth_bps` via the composed
  `lstm_provider.predict(state)`, build features with the **shared** `src/rl/features.build_state(state)` (reading
  `feature_spec`+`norm_constants` from the checkpoint), take `argmax Q` (epsilon=0). Configured once on the edge
  (`edge.abr_factory = lambda: DQNABR(...)`); all users on that edge share the policy. The topology-driven
  `Simulator` needs no per-algorithm branching.

### Comparison (`compare.py`)
- `Simulator.run(..., run_label=...)` → logs to `logs/<label>/...`; `return_summary=True` → returns stats + QoE.
- Run baseline / LSTM / DQN on the **same** trace+manifest; print a comparison table.

## 14. Segment-based fetching + adaptive playback (round 2) — BUILT, TRAINED & VERIFIED (2026-07-11)

The §13 headline said pipelined/segment fetching was the binding next lever. Round 2
built it and it worked: **the per-frame RTT floor is broken.**

**What shipped** (commit 2c05818): `session.step_segment()` fetches S frames per
request (one ABR decision + one TCP transfer); `step()` is now a 1-frame adapter so
S=1 is bit-identical to §13. Adaptive playback (`ClientBuffer.playback_rate_min`,
dash.js-style 0.9x floor, QoE′ gains −10·∫(1−rate)dt). Multi-seed evals
(`--eval-seeds` averages jitter seeds; sweep trains 2 seeds/config) — fixes the §9
one-off-spike checkpoint problem. `--segment-frames`/`--playback-rate-min` across
train/eval/compare/run; LSTM regen at segment granularity.

**Result (DQN_REPORT §10)**: the segment-size sweep {1,5,8,10,15,30} traces a clean
**inverted-U in QoE′ peaking at S=5** (69.4), bad at both ends for opposite reasons —
S=1 stalls 19 s (RTT floor), S=30 stalls 20 s (only 10 decisions/clip, can't react
mid-segment; the deliberate measure-and-reject worked). Winner **S=5, μ=4.3,
+lstm_pred: QoE′ 77.3, legacy QoE 92.2, quality 0.809, stall 0.56 s** — legacy QoE
finally off 0. compare.py at S=10: DQN QoE 100 / quality 0.921 / zero stall; the LSTM
rule climbs to quality 0.426 (was 0.030) because segments finally let the client
*measure real bandwidth*. lstm_pred ablation still marginal (mean −1.78, noisy).

**Residual levers (not transport-fundamental)**: request pacing (eager fetch overflows
the 5 s buffer → rule ABRs drop 56–84 frames; the DQN avoids it by watching the
buffer); more training seeds (seed 42→82 vs seed 43→62 at the winner config);
S-matched final eval; reconsider the LSTM selection metric now that stalls are rare
(log1p won low-bw MAE but lost aggregate MAE to persistence).

**Round 3 close-out (2026-07-11, DQN_REPORT §10.8–10.9)**: the S-matched 8-seed run
gives the honest robust winner — **S=8, μ=4.3, lstm-off: QoE′ 74.6 ± 19.8** (all four
S∈{5,8}×lstm configs statistically tied; the lstm_pred feature is now confirmed
irrelevant). Key reversal: with segmentation making the link comfortable, the best
**fixed** arm (always-medhigh, QoE′ 90.3, zero stall) is NOT beaten by the DQN's robust
mean — the good seeds (~90+) match it but ~40% underperform, so the binding constraint
is now **RL training variance**, echoing the original 4G no-headroom finding. Next
levers: RL variance reduction (n-step/PER/dueling/ensembling), a harder/more variable
network regime with real adaptation headroom, and request pacing for the rule baselines.
